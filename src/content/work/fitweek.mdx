<Section n="01" title="The problem">

Most people wear a fraction of what they own, because deciding what to wear happens at 7am, half awake, without checking the weather or remembering what's in the laundry. FitWeek moves that decision to Sunday: plan the week once, swipe to adjust, and get dressed without thinking.

- **Classification:** Cloud Vision returns labels like "Active Shirt" or "Blazer". A lookup maps them to seven categories, falling back from exact match to word match to substring match, and reports what it matched so the app can show its confidence.
- **Background removal** runs on the server with a local ONNX model, and fails soft, so a bad cut-out never blocks saving a garment.
- **Try-on** sends the garment and your model photo to IDM-VTON through a Gradio client and returns the rendered look to the app.

</Section>

<Section n="03" title="The recommender, deliberately boring">

The outfit engine is a pure TypeScript library with no LLM in it. Each garment gets a score from six weighted signals: how long since you wore it (30%), fit for the day's weather (30%), variety (15%), freshness (10%), tag fit such as wool for cold days (10%) and colour neutrality (5%). Outfits are built from templates and scored again for completeness, cohesion and colour harmony. The week planner then avoids reusing any garment already planned that week, and only relaxes that rule when the wardrobe runs out.

Laundry, skipped days and deleted items are filtered out before scoring, so the plan only ever uses what's clean.

The playground above runs this exact library, copied from the FitWeek repo, against a sample wardrobe and Nairobi's live forecast.

<Aside>Deterministic means testable. Every rule here has a unit test, and the same 18 tests run in this site's CI.</Aside>
</Section>

<Section n="04" title="Engineering">

- A pnpm monorepo: the Expo app, the Express 5 API and shared libraries. API clients are generated from the OpenAPI spec with Orval, and requests are validated with Zod.
- Postgres with Drizzle ORM, with a GIN index on garment tags. Supabase handles auth (email and Google) and storage.
- The API ships to Cloud Run with liveness and readiness probes; the Android app builds with EAS. CI typechecks, tests and builds on every push.

</Section>

<Section n="05" title="What I'd change">

- Learn from swipes: today the weights are fixed; a rejected suggestion should nudge them.
- Extract colour from pixels instead of label hints.
- Add occasion (work, gym, wedding) as a planning input next to the weather.

</Section>
